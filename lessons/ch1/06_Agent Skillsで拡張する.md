# Agent Skillsで拡張する

Claudeが場面ごとに持ち替えている"道具"＝Agent Skills（エージェントスキル）の正体を知る回です。標準スキルの仕組みと安全な見極め方を押さえたうえで、最後には皆さん専用のスキルを1本作って動かします。

---

## STEP1　スキルが動く瞬間（🎬 体験する）

**ゴール：** Claudeが「道具」を持ち替える瞬間を目撃する（目安20分）

**🎙️ 導入トーク**
「今日は少し不思議な話から始めます。これまでの授業で、ClaudeはExcelを作ったり、Webを検索したり、ファイルを整理したりしましたよね。実は、あのときClaudeは場面ごとに"道具"を持ち替えていたんです。その道具の正体を、今日は見に行きます。」

1. claude.ai で新しいチャットを開く
2. 「最近の〇〇業界のニュースを調べて、要点を3つ教えて」と頼む（Web検索の道具が動く）
3. 画面に出る「検索中…」「ファイルを作成中…」のような表示に注目する
4. 続けて「その内容を1枚のスライドにして」と頼む（ファイル生成の道具に持ち替わる）
5. Claudeがどの場面でどの道具を選んだか、みんなで言い合ってみる

**✨ 種明かし**
「この道具の正体が『Agent Skills（エージェントスキル）』です。Web検索・コード実行・ファイル操作……Claudeは頼まれた仕事に合わせて、自分でスキルを選んで使っています。そして今日の一番のお知らせはこれです——このスキル、自分で作れます。今日の最後には、皆さん専用のスキルが1本できあがります。」

---

## STEP2　スキルの仕組み（📖 学ぶ）

**ゴール：** 標準スキルの種類と「いつ・なぜ」動くかを知る（目安30分）

**🎙️ 導入トーク**
「まず、最初から入っている『標準スキル』を整理します。どこで確認できて、どういうときに動くのか。ここが分かると、Claudeの動きが読めるようになります。」

| 標準スキルの例 | 何をする道具か | 動く場面の例 |
| --- | --- | --- |
| Web検索 | 最新情報をインターネットから取ってくる | 「最近の」「今の」など鮮度が要る質問 |
| コード実行 | 計算・データ処理をプログラムで正確に行う | 集計・グラフ・複雑な計算 |
| ファイル操作 | Excel・Word・PDF・スライドを読み書きする | 第2回でやった成果物づくり全般 |

**💡 スキルはどこで確認できる？　いつ動く？**
**確認場所：** claude.ai の設定（機能・ケイパビリティの画面）に、使えるスキルの一覧とオン/オフがあります。**いつ動くか：** 皆さんが指定するのではなく、Claudeが依頼文を読んで「この仕事にはこの道具が要る」と自分で判断して使います。だから、頼み方に「最新の情報で」「正確に計算して」のような手がかりを入れると、適切なスキルが選ばれやすくなります。

**✨ 種明かし**
「ポイントは『スキルは自動で選ばれる』ということ。皆さんがボタンを押すのではなく、依頼の書き方が道具選びのヒントになる。第2回で学んだ"型"に『最新情報で』『計算はコード実行で正確に』と一言足すだけで、Claudeの道具選びが上手になります。」

---

## STEP3　安全な使い方（📖 学ぶ）

**ゴール：** 第三者スキルのリスクと見極め方を身につける（目安25分）

**🎙️ 導入トーク**
「スキルは自分で作れるだけでなく、他の人が作ったものを追加することもできます。便利です。ただ、ここで一度立ち止まってください。スキルとは『Claudeへの指示書』です。誰かの指示書を自分のClaudeに読ませる——その意味を考えてから使いましょう。」

| チェック項目 | 確認すること | 危険なサイン |
| --- | --- | --- |
| ① 出どころ | 公式・実名・信頼できる組織が配布しているか | 出所不明の共有リンク・匿名の配布 |
| ② 中身 | SKILL.mdを開いて指示を読んだか（読める形か） | 中身が読めない・難読化されている |
| ③ 求める権限 | 仕事に必要な範囲のアクセスだけか | 目的に不要なファイル・外部送信を求める |
| ④ 挙動 | 「データをどこかへ送る」指示が入っていないか | 外部URLへの送信・情報収集の指示 |

**✨ 種明かし**
「見極めの合言葉は『読んでから入れる』。スキルはただのテキストファイルなので、必ず中身を読めます。読んで意味が分からなければ、Claude本人に『このスキルは何をするもの？リスクは？』と読ませて説明させればいい。会社で使う場合は、勝手に追加せずIT担当への確認を挟むこと。ここを守れば、スキルは安全に拡張できます。」

---

## STEP4　SKILL.mdの中身（📖 学ぶ）

**ゴール：** SKILL.mdの構造を読めるようになる（目安35分）

**🎙️ 導入トーク**
「いよいよスキルの中身です。カスタムスキルの本体は『SKILL.md』という1枚のテキストファイル。プログラミングではありません。日本語で書く"新人向けの業務マニュアル"だと思ってください。実物を見てみましょう。」

**SKILL.md（例：口コミ返信スキル）**

```
---（ここからフロントマター＝スキルの名札）
name: kuchikomi-reply
description: お客様の口コミ・レビューへの返信文を作る。
  「口コミに返信」「レビュー返信」と言われたら使う。
---（ここまで名札。以下が本文＝手順書）

# 口コミ返信スキル

## 手順
1. 口コミの内容を読み、良い点への言及と改善要望を分ける
2. 感謝 → 具体的な言及 → 今後の対応 → 再来のお誘い の順で返信を作る
3. 3パターン（丁寧・親しみ・簡潔）を提示して選んでもらう

## ルール
- 返信は200字以内。言い訳をしない。個人情報を書かない
- ネガティブな口コミほど、反論せずまず受け止める

## 参考
- 過去の良い返信例は references/henshin-rei.md を参照
```

| 構成要素 | 役割 | 書くこと |
| --- | --- | --- |
| フロントマター | スキルの名札。Claudeが「いつ使うか」を判断する材料 | 名前と、発動のきっかけになる言葉（トリガー） |
| 本文 | 仕事の手順書 | 手順・ルール・良い例と悪い例 |
| scripts / references | 添付の道具箱と資料集（必要なときだけ） | 定型処理のスクリプト、参考資料・テンプレート |

**✨ 種明かし**
「注目してほしいのは description（説明文）です。Claudeはここを読んで『今この道具を使うべきか』を判断します。つまり**トリガーになる言葉を具体的に書くほど、狙った場面でスキルが動く**。本文は皆さんが新人に渡す手順書と同じ書き方でOK。プログラミング不要、というのが実感できたと思います。」

## STEP5　スキルを作る（✋ 実践する）

**ゴール：** 自分の業務スキルを1本作って動かす（目安50分）

**🎙️ 導入トーク**
「今日の本番です。自分の繰り返し業務を1つ選んで、スキルにします。ゼロから書く必要はありません。『skill-creator』という、スキルを作るためのスキルがあって、Claudeと会話しながら組み立ててくれます。」

1. スキルにしたい業務を1つ選ぶ（毎回同じ手順でやっている仕事：週報づくり・議事録整形・問い合わせ一次回答・チェックリスト確認 など）
2. Claudeに「skill-creatorを使って、〇〇のスキルを作りたい」と話しかける
3. 質問に答えながら、手順・ルール・トリガーの言葉を伝えていく（新人に口頭で教えるつもりで）
4. できあがったSKILL.mdを読んで、「ここは違う」を2〜3箇所直してもらう
5. スキルを登録し、新しいチャットでトリガーの言葉を使って呼び出しテストをする
6. 狙い通りに動かなければ、descriptionのトリガー語を具体的にして再テスト

**💡 うまく動かないときのチェックポイント／MCPコネクタとの違い**
**動かないときは上から順に：** ①descriptionに発動のきっかけ語が入っているか → ②手順が曖昧な日本語になっていないか → ③1つのスキルに仕事を詰め込みすぎていないか（1スキル1業務が基本）。
**コネクタとの違い：** 第3回のコネクタは「外部ツールへの**通り道**」、スキルは「仕事の**やり方**」。Driveの資料を読むのはコネクタ、読んだ後にどう整理するかがスキル、と覚えてください。

**✨ 種明かし**
「いま皆さんがやったのは、**自分のノウハウの道具化**です。頭の中にしかなかった手順が、ファイルになり、いつでも同じ品質で再現される。大量の情報整理・文章レビュー・FAQづくり・比較検討——どんな業務も、手順が言葉にできればスキルにできます。1本作れた人は、もう何本でも作れます。」

### STEPごとの講師メモ

- **STEP1／「道具箱」の比喩で通す：** 「Claude＝職人、スキル＝道具箱の中の道具」で最後まで通すと迷子が出ない。体験では処理中の表示（どのスキルが動いているか）を指差しで実況すると「持ち替え」が見える。（確認：「Claudeは道具を持ち替えて働いている」が腹落ちしていればOK。）
- **STEP2／設定画面を全員で開く：** スキル一覧の画面を全員で実際に開いて眺める時間を取る。「こんなに道具を持っていたのか」という発見が、後半のカスタムスキルづくりへの期待につながる。（確認：標準スキル3種と「自動で選ばれる」ことが言えればOK。）
- **STEP3／怖がらせすぎない：** 安全パートは重要だが、恐怖で締めると後半の「作る」意欲が下がる。「包丁と同じで、出どころと使い方さえ確かなら便利な道具」というトーンでまとめ、「自作スキルなら中身は全部自分が書いたもの＝一番安全」と次のSTEPへ橋を架ける。（確認：チェック4項目と「読んでから入れる」が言えればOK。）
- **STEP4／コード画面への抵抗を下げる：** 黒い画面が出た瞬間に身構える人がいる。「これはただのメモ帳の中身。色が付いているだけ」と先に言う。コピーボタンで手元に持ち帰れることも伝えると安心する。（確認：「名札（いつ使うか）＋手順書（どうやるか）」の2階建てが言えればOK。）
- **STEP5／題材選びが5割：** 「手順が3〜5ステップで言える仕事」を選ばせると成功率が高い。大きすぎる題材（営業全部など）は「その中の1工程だけ」に絞らせる。完成者から順に呼び出しテストのデモをしてもらい、発動の瞬間の歓声を全体で共有する。（確認：全員が自作スキルを登録し、呼び出しテストに成功していればOK。）
- **STEP6／宿題（任意）：** 「今日のスキルを1週間実務で使い、直したくなった箇所を3つメモしてくる」を宿題に。スキルは使って直すことで完成する、というメッセージとセットで。
